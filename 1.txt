# yyds-fswatch 最终实施方案

## 一、API 设计：四层渐进式 API

核心理念：**一个 `FSWatcher` 类，四种使用方式**。开发者根据场景选择最合适的层级。

---

### 🏆 Level 1：装饰器模式（主打 API）

**场景**：热重载服务器、构建工具、日常自动化

```python
from yyds_fswatch import FSWatcher

# 支持同时监听多个路径，支持传入列表或单个路径
w = FSWatcher(['/var/log', './src'], recursive=True)

@w.on('modified')
def on_modified(event):
    print(f'文件修改: {event.src_path}')

# 支持使用 '*' 或 'any' 监听所有事件
@w.on('*')
def on_any_event(event):
    print(f'任何变动: {event.event_type} - {event.src_path}')

w.start()  # 阻塞运行，Ctrl+C 优雅退出并自动清理系统 FD 和资源
```

### ⚡ Level 2：一行回调（快速脚本）

```python
from yyds_fswatch import watch
# 支持多路径聚合
watch(['./src', './tests'], on_change=lambda e: print(f'{e.event_type}: {e.src_path}'))
```

### 🔄 Level 3：同步迭代器（管道处理）

```python
from yyds_fswatch import FSWatcher
with FSWatcher('.') as w:
    for event in w:
        print(f'{event.event_type}: {event.src_path}')
```

### 🚀 Level 4：异步迭代器（asyncio 应用）

```python
import asyncio
from yyds_fswatch import FSWatcher

async def main():
    async with FSWatcher(['.', '../other_dir']) as w:
        async for event in w:
            await call_ai_api(event.src_path)

asyncio.run(main())
```

## 二、事件模型设计

```python
@dataclass
class FSEvent:
    event_type: str         # 'created' | 'modified' | 'deleted' | 'moved' | 'closed'
    src_path: str           # 源路径（绝对路径）
    dest_path: str = ""     # 仅 moved 事件有值
    is_directory: bool = False
```

对齐 watchdog 的事件语义（`created` / `modified` / `deleted` / `moved`），但用单一 `FSEvent` + `is_directory` 标志替代 watchdog 的十几个子类，更简洁。

FSWatcher(

### 5.1 整体事件流架构

```
[ OS 内核 (支持多路径聚合) ]
     │
     ├─► Linux  : inotify fd ─────► loop.add_reader() ──┐
     ├─► macOS  : FSEvents ────────► 守护线程桥接 ───────┼─► [ 异步生产者 Collector ]
     ├─► Windows: ReadDirChangesW ─► 后台线程桥接 ───────┘         │
     └─► 降级   : os.stat 轮询 ────► asyncio.sleep 定时 ──────────┘
                                                                   │
                                                          ┌────────▼────────┐
                                                          │ .gitignore 过滤 │
                                                          │ (LRU 匹配缓存)  │
                                                          └────────┬────────┘
                                                                   │
                                                          ┌────────▼────────┐
                                                          │  防抖状态机引擎  │
                                                          │ (滑窗合并/cookie)│
                                                          └────────┬────────┘
                                                                   │
                                                          ┌────────▼────────┐
                                                          │ asyncio.Queue   │
                                                          └────────┬────────┘
                                                                   │
                                              ┌────────────────────┼────────────────────┐
                                              │                    │                    │
                                     @w.on() 装饰器         for event in w      async for event in w
                                     watch() 回调           (同步迭代器)         (异步迭代器)
```

### 5.2 Linux 平台驱动：ctypes inotify 深度实现

> [!IMPORTANT]
> Python `os` 模块**不提供** `inotify_init1` / `IN_CREATE` 等 API。必须通过 `ctypes` 调用 libc。

#### 5.2.1 ctypes 绑定

```python
import ctypes
import ctypes.util

libc = ctypes.CDLL(ctypes.util.find_library('c') or 'libc.so.6')

# 系统调用绑定
inotify_init  = libc.inotify_init     # () -> int (fd)
inotify_add_watch = libc.inotify_add_watch  # (fd, path_bytes, mask) -> int (wd)
inotify_rm_watch  = libc.inotify_rm_watch   # (fd, wd) -> int

# 设置返回类型和参数类型
inotify_init.argtypes = []
inotify_init.restype = ctypes.c_int
inotify_add_watch.argtypes = [ctypes.c_int, ctypes.c_char_p, ctypes.c_uint32]
inotify_add_watch.restype = ctypes.c_int
inotify_rm_watch.argtypes = [ctypes.c_int, ctypes.c_int]
inotify_rm_watch.restype = ctypes.c_int
```

#### 5.2.2 inotify 常量定义

```python
class InotifyMask:
    IN_CREATE      = 0x00000100
    IN_DELETE      = 0x00000200
    IN_MODIFY      = 0x00000002
    IN_MOVED_FROM  = 0x00000040
    IN_MOVED_TO    = 0x00000080
    IN_CLOSE_WRITE = 0x00000008
    IN_ATTRIB      = 0x00000004
    IN_DELETE_SELF  = 0x00000400
    IN_MOVE_SELF    = 0x00000800
    IN_ISDIR       = 0x40000000
    IN_IGNORED     = 0x00008000
    IN_Q_OVERFLOW  = 0x00004000

    # 我们关注的事件集合
    WATCH_MASK = (IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_FROM |
                  IN_MOVED_TO | IN_CLOSE_WRITE | IN_ATTRIB |
                  IN_DELETE_SELF | IN_MOVE_SELF)
```

#### 5.2.3 非阻塞 + asyncio 绑定

```python
import fcntl
import os

fd = inotify_init()
# 设为非阻塞
flags = fcntl.fcntl(fd, fcntl.F_GETFL)
fcntl.fcntl(fd, fcntl.F_SETFL, flags | os.O_NONBLOCK)
# 设为 close-on-exec
fcntl.fcntl(fd, fcntl.F_SETFD, fcntl.FD_CLOEXEC)

# 零线程核心：挂载到 asyncio 事件循环
loop.add_reader(fd, self._handle_raw_read)
```

#### 5.2.4 inotify_event 字节流解析（含断包重组）

inotify 事件的 C 结构体：
```c
struct inotify_event {
    int      wd;       // 4 bytes - watch descriptor
    uint32_t mask;     // 4 bytes - 事件类型
    uint32_t cookie;   // 4 bytes - rename 配对标识
    uint32_t len;      // 4 bytes - 文件名长度（含填充）
    char     name[];   // 变长 - 文件名
};
// 固定头部 = 16 bytes
```

解析算法（关键：必须处理残留字节）：

```python
import struct

INOTIFY_EVENT_HEADER_SIZE = 16  # wd(4) + mask(4) + cookie(4) + len(4)

class InotifyParser:
    def __init__(self):
        self._buffer = b''  # 残留缓冲区

    def parse(self, data: bytes) -> list:
        self._buffer += data
        events = []
        offset = 0

        while offset + INOTIFY_EVENT_HEADER_SIZE <= len(self._buffer):
            wd, mask, cookie, name_len = struct.unpack_from(
                'iIII', self._buffer, offset
            )
            total_len = INOTIFY_EVENT_HEADER_SIZE + name_len

            # 检查是否有完整的事件（含变长文件名部分）
            if offset + total_len > len(self._buffer):
                break  # 不完整，等下次 read 拼接

            # 提取文件名（去除 null 填充）
            name_bytes = self._buffer[offset + INOTIFY_EVENT_HEADER_SIZE:
                                      offset + total_len]
            name = name_bytes.rstrip(b'\x00').decode('utf-8', errors='replace')

            events.append(InotifyRawEvent(wd=wd, mask=mask, cookie=cookie, name=name))
            offset += total_len

        # 保留未解析完的残留字节
        self._buffer = self._buffer[offset:]
        return events
```

#### 5.2.5 递归目录注册（含 .gitignore 剪枝与多路径支持）

```python
def _register_recursive(self, root_path: Path):
    """递归注册 inotify watch，同时应用 .gitignore 剪枝"""
    # 支持在初始化时遍历多路径
    for dirpath, dirnames, filenames in os.walk(root_path):
        path = Path(dirpath)

        # .gitignore 剪枝：从 dirnames 中移除被忽略的子目录
        # 这样 os.walk 不会进入这些目录，也不会为它们注册 watch
        dirnames[:] = [
            d for d in dirnames
            if not self._ignore_filter.is_ignored(path / d, is_dir=True)
        ]

        # 为当前目录注册 watch
        wd = inotify_add_watch(self._fd, str(path).encode(), InotifyMask.WATCH_MASK)
        if wd < 0:
            continue  # 权限不足等情况跳过
        self._wd_to_path[wd] = path
        self._path_to_wd[path] = wd
```

#### 5.2.6 动态子目录绑定

当收到 `IN_CREATE | IN_ISDIR` 事件时，自动为新建的子目录注册 watch：

```python
def _on_raw_event(self, event: InotifyRawEvent):
    if event.mask & InotifyMask.IN_CREATE and event.mask & InotifyMask.IN_ISDIR:
        new_dir = self._wd_to_path[event.wd] / event.name
        if not self._ignore_filter.is_ignored(new_dir, is_dir=True):
            self._register_recursive(new_dir)  # 递归注册新子目录树
```

### 5.3 智能防抖算法设计

#### 5.3.1 防抖状态机

维护 `_pending_events: dict[Path, PendingState]` 和 `_pending_timers: dict[Path, TimerHandle]`。

```python
@dataclass
class PendingState:
    event_type: str
    is_directory: bool
    dest_path: str = ""
```

**合并规则**：

| 前一状态 | 当前事件 | 合并结果 | 理由 |
| :--- | :--- | :--- | :--- |
| `created` | `modified` | `created` | 新建后修改，对外就是"新建" |
| `created` | `deleted` | ∅（丢弃） | 新建后立马删，等于无事发生 |
| `modified` | `modified` | `modified` | 多次修改合并为一次 |
| `deleted` | `created` | `modified` | 删了又建回来，等于内容变了 |
| 任意 | `moved` | `moved`（直接放行） | 移动事件不参与防抖 |

#### 5.3.2 防抖流程

```python
def _push_to_debounce(self, path: Path, event_type: str, is_dir: bool, dest_path: str = ""):
    # 1. .gitignore 快速过滤
    if self._ignore_filter.is_ignored(path, is_dir=is_dir):
        return

    # 2. moved 事件直接放行（不防抖）
    if event_type == 'moved':
        self._emit_event(FSEvent(event_type='moved', src_path=str(path),
                                 dest_path=dest_path, is_directory=is_dir))
        return

    # 3. 取消已有定时器
    if path in self._pending_timers:
        self._pending_timers[path].cancel()

    # 4. 状态机合并
    old = self._pending_events.get(path)
    if old:
        if old.event_type == 'created' and event_type == 'modified':
            new_type = 'created'
        elif old.event_type == 'created' and event_type == 'deleted':
            self._pending_events.pop(path, None)
            self._pending_timers.pop(path, None)
            return  # 丢弃
        elif old.event_type == 'deleted' and event_type == 'created':
            new_type = 'modified'
        else:
            new_type = event_type
    else:
        new_type = event_type

    # 5. 更新挂起状态
    self._pending_events[path] = PendingState(event_type=new_type, is_directory=is_dir)

    # 6. 重新注册延时任务（零线程开销）
    timer = self._loop.call_later(self.debounce, self._flush_event, path)
    self._pending_timers[path] = timer

def _flush_event(self, path: Path):
    """防抖时间窗口关闭，正式放行事件"""
    state = self._pending_events.pop(path, None)
    self._pending_timers.pop(path, None)
    if state:
        event = FSEvent(event_type=state.event_type, src_path=str(path),
                        is_directory=state.is_directory)
        self._queue.put_nowait(event)
```

#### 5.3.3 Rename Cookie 配对算法

Linux inotify 的重命名产生两个事件：`IN_MOVED_FROM`（旧路径，带 cookie）和 `IN_MOVED_TO`（新路径，带相同 cookie）。

```python
# 数据结构
_move_cookies: dict[int, tuple[Path, float]] = {}  # cookie -> (old_path, timestamp)

def _handle_move_from(self, cookie: int, old_path: Path, is_dir: bool):
    """收到 IN_MOVED_FROM，暂存 cookie"""
    self._move_cookies[cookie] = (old_path, time.monotonic(), is_dir)
    # 注册超时清理（100ms 内如果没收到 MOVED_TO，降级为 deleted）
    self._loop.call_later(0.1, self._expire_cookie, cookie)

def _handle_move_to(self, cookie: int, new_path: Path, is_dir: bool):
    """收到 IN_MOVED_TO，查找配对"""
    if cookie in self._move_cookies:
        old_path, _, _ = self._move_cookies.pop(cookie)
        # 配对成功 → 合并为 moved 事件
        self._push_to_debounce(old_path, 'moved', is_dir, dest_path=str(new_path))
    else:
        # 文件从外部移入监控目录 → 等同于 created
        self._push_to_debounce(new_path, 'created', is_dir)

def _expire_cookie(self, cookie: int):
    """Cookie 超时未配对 → 降级为 deleted"""
    if cookie in self._move_cookies:
        old_path, _, is_dir = self._move_cookies.pop(cookie)
        self._push_to_debounce(old_path, 'deleted', is_dir)
```

### 5.4 .gitignore 过滤引擎

#### 5.4.1 规则解析

将 `.gitignore` 的每条规则翻译为编译好的 `re.Pattern`：

| gitignore 语法 | 翻译为正则 | 说明 |
| :--- | :--- | :--- |
| `node_modules/` | `^(.*/)?node_modules/` | 匹配任何层级的 node_modules 目录 |
| `*.log` | `^(.*/)?[^/]*\.log$` | 匹配任何层级的 .log 文件 |
| `/dist` | `^dist(/\|$)` | 仅匹配根目录下的 dist |
| `!important.log` | 取反规则 | 从忽略列表中排除 |
| `build/` | `^(.*/)?build/` | 匹配任何层级的 build 目录 |

#### 5.4.2 两层过滤策略（带 LRU 缓存优化）

```python
from functools import lru_cache

class GitIgnoreFilter:
    def __init__(self, gitignore_path: Path):
        self._fast_dirs: set = set()      # 快速路径：常见忽略目录名
        self._patterns: list = []          # 编译好的正则规则链
        self._negation_patterns: list = [] # 取反规则
        self._parse(gitignore_path)

    def _parse(self, path: Path):
        """解析 .gitignore 文件"""
        for line in path.read_text().splitlines():
            line = line.strip()
            if not line or line.startswith('#'):
                continue
            if line.startswith('!'):
                self._negation_patterns.append(self._to_regex(line[1:]))
            else:
                # 常见目录名直接加入快速集合
                stripped = line.rstrip('/')
                if '/' not in stripped and '*' not in stripped and '?' not in stripped:
                    self._fast_dirs.add(stripped)
                self._patterns.append(self._to_regex(line))

    # 使用 LRU 缓存匹配结果，保证高频触发时 O(1) 性能
    @lru_cache(maxsize=4096)
    def is_ignored(self, path: Path, is_dir: bool = False) -> bool:
        rel = str(path.relative_to(self._root))
        if is_dir:
            rel += '/'

        # 层级1：快速路径 O(1) — 检查路径中是否包含被忽略的目录名
        for part in path.parts:
            if part in self._fast_dirs:
                return True

        # 层级2：正则匹配
        matched = any(p.search(rel) for p in self._patterns)
        if matched:
            # 检查取反规则
            negated = any(p.search(rel) for p in self._negation_patterns)
            return not negated
        return False
```

#### 5.4.3 过滤时机（两个关键节点）

1. **建立 inotify watch 时剪枝**：在 `os.walk` 遍历目录树时，被忽略的子目录直接从 `dirnames` 中移除，不注册 FD → 从源头节省系统资源
2. **事件流中过滤**：在防抖引擎入口处过滤，被忽略文件的变动事件直接丢弃 → 不进入防抖队列、不占内存

### 5.5 多模式统一架构

所有 4 种 API 模式共享同一套底层事件管道：

```
平台驱动 → .gitignore 过滤 → 防抖引擎 → asyncio.Queue
                                              ↑
                                     所有模式都从这里消费
```

**模式实现差异**：

| 模式 | 内部机制 |
| :--- | :--- |
| `@w.on()` 装饰器 + `w.start()` | 内部启动 `asyncio.run()` 事件循环，消费队列并分发到对应回调。捕获 `KeyboardInterrupt` 优雅退出，释放系统 FD。 |
| `watch()` 一行回调 | 同上，只是回调函数统一为 `on_change` |
| `with w: for event in w:` | 内部在后台线程启动事件循环，主线程通过 `threading.Event` 等待，从 `queue.Queue`（线程安全）读取 |
| `async with w: async for event in w:` | 直接复用调用者的事件循环，从 `asyncio.Queue` 读取 |

**哨兵退出机制**：
```python
_STOP = object()

async def __aexit__(self, *exc):
    self._stop_monitoring()
    self._queue.put_nowait(_STOP)

async def __anext__(self) -> FSEvent:
    event = await self._queue.get()
    if event is _STOP:
        raise StopAsyncIteration
    return event
```

### 5.6 Windows 平台驱动

- 通过 `ctypes` 封装 `kernel32.dll` 的 `CreateFileW` + `ReadDirectoryChangesW`
- 在后台线程中阻塞读取（Windows 原生支持 `bWatchSubtree=True` 递归）
- 通过 `loop.call_soon_threadsafe(queue.put_nowait, event)` 投递到主事件循环
- 仅需一个后台线程

### 5.7 macOS 平台驱动

- 通过 `ctypes` 封装 `CoreServices` 的 `FSEventStreamCreate` / `FSEventStreamStart`
- 在守护线程中运行 `CFRunLoopRun` 驱动事件流
- 同样通过 `call_soon_threadsafe` 跨线程投递

### 5.8 Polling 降级方案

- 基于 `os.stat` 的目录树快照差异对比（比对 `mtime`、`size`）
- 使用 `asyncio.sleep(interval)` 定时轮询
- 作为所有平台的万能降级方案（NFS、Docker 挂载卷等场景）

## 六、边界情况防御

| 边界情况 | 处理策略 |
| :--- | :--- |
| **inotify FD 耗尽** | 捕获 `errno.ENOSPC`，打印友好提示并自动切换到 Polling 模式 |
| **缓冲区截断** | `InotifyParser` 维护残留字节缓冲区，与下次读取拼接后再解析 |
| **Rename 超时未配对** | 100ms 超时后将 `IN_MOVED_FROM` 降级为 `deleted` 事件 |
| **监控目录被删除** | 捕获 `IN_DELETE_SELF` / `IN_IGNORED`，触发 watcher 停止或重启 |
| **权限不足** | `inotify_add_watch` 返回 -1 时跳过该目录，打印警告 |
| **协程泄漏** | 哨兵对象 `_STOP` 确保 `async for` 优雅退出 |

### 手动验证
```bash
# 启动 CLI 监控
yyds-fswatch . --recursive --debounce 0.05

# 另一个终端操作
touch test.txt            # → created
echo "hello" > test.txt   # → modified（防抖合并为单次）
mv test.txt test2.txt     # → moved（带 dest_path）
rm test2.txt              # → deleted
mkdir node_modules && touch node_modules/x.js  # → 无事件（.gitignore 过滤）
```
